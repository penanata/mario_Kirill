# Деревья — контекст проекта

## Бизнес
- Интернет-продажи садовых растений и озеленения (доставка + посадка).
- Канал сейчас: Avito (объявления → переписка → телефон/адрес → расчёт → дата).
- Также есть сайт; другие каналы планируются.
- Поставщик один: розница Москва / Подольск.
- Каталог ≈ 150 позиций.
- Потолка по заказам нет: цель — масштабировать менеджеров и объём.

## Команда и роли
- **Наталия** — объявления Avito, клиенты с Avito, передача заказа поставщику.
- **Дарья** — карточки Avito, ответы клиентам (в т.ч. телефон), связь с поставщиком; в перспективе ROM.
- **Светлана** — полный фин учёт (сейчас фактически нет из‑за хаоса).
- **Поставщик** — собрать, доставить, посадить.

## Объём
- Сейчас: единицы в день (пример: 4 / 1).
- Ближняя цель: 3–5 заказов в день на каждого из трёх менеджеров, далее рост.

## Процесс заказа
1. Объявление на Avito.
2. Вопросы клиентов в чате.
3. Телефон и адрес → расчёт.
4. Согласование даты доставки и посадки.
5. Поставщик собирает, везёт, сажает (или отправка ТК, если нельзя передать наличные).

## Деньги
- Закуп поставщика и цена клиенту; разница = валовая прибыль.
- Из прибылей: зарплаты, налоги, банк, реклама Avito.
- **Оплата:** чаще наличные поставщику при получении; иногда на р/с Наталии (например отправка через ТК / СДЭК и аналоги — некому передать наличные).
- Предоплата бывает, чаще — при получении.
- В заказе обязательно: сколько получит поставщик, сколько получит бизнес, наличные или уже на р/с.

## Источник правды
- Наиболее актуальные наличие и **цены поставщика** — из его сообщений (сейчас чат). Критично не пропускать смену цены.

## Инструменты сейчас
- YouGile, Telegram, Avito, Google Таблицы.
- Команда — с компьютеров; поставщик — с телефона.

## Приоритеты (все важны)
1. Не пропускать цены поставщика.
2. Календарь заказов (кто / куда / когда).
3. Деньги и прибыль (для Светланы и контроля маржи).

## Цель системы
Единая структура: заказы + календарь + прайс/остатки/фото + задачи + счета + мобильный вид поставщика + (желательно) Telegram-апдейты.

## Решение
- Архитектура: **C — своя лёгкая система**, быстрая и простая.
- MVP: прайс с историей цен → заказы + календарь + оплата → мобильный день поставщика → позже прибыль и Telegram.

## Права на цены
- Цену поставщика в системе **преимущественно меняет поставщик** (с телефона).
- Менеджеры могут поправить при необходимости.
